先查行为变化

确认改动是否影响旧接口、旧页面和已有流程。

02

再查边界条件

空值、异常分支、权限和失败提示要优先检查。

03

最后整理评审上下文

把改动原因、范围和已验证结果说清楚，评审效率会高很多。

建议核对清单

  • 先跑最接近实际使用路径的验证，而不是只看 happy path。
  • 高风险改动应补充影响范围说明。
  • 提交前先清理无关日志和临时代码。

常见问题

AI 能替代代码评审吗？

不能，但很适合先做一轮自查。

最值得先查什么？

行为回归、边界条件和错误提示通常最值得优先查。

先看报错类型

再看 Network 请求

把报错页面和请求结果对应起来，避免只盯控制台文字。

03

最后做最小复现

只保留一条关键路径，能更快看清问题真正位置。

建议核对清单

  • 先刷新并保留 console、network 两边的关键记录。
  • 发现报错时记录浏览器、系统和复现步骤。
  • 排查跨域或缓存问题时，记得说明环境差异。

常见问题

控制台没报错就说明前端没问题吗？

不一定，很多问题会出现在 network 或页面逻辑层。

需要把全部日志都发给团队吗？

建议先提炼关键报错和复现步骤。

01

先确认请求方法

GET、POST、PUT 和 DELETE 的差异会直接影响接口返回，不要默认复制旧命令。

02

再核对请求头

Authorization、Content-Type 和 Cookie 是最常见的差异点。

03

最后保存可复现命令

保留一条最小可复现的 curl 示例，便于前后端快速对齐。

建议核对清单

  • 先用最短命令确认域名和状态码可达，再补 header 和 body。
  • 如果和前端结果不一致，先比对 header、token 和 cookie。
  • 把失败请求和成功请求各留一条，便于后续对照。

常见问题

为什么 curl 成功但页面请求失败？

通常是 cookie、跨域、浏览器环境或 header 不同。

curl 命令要不要保留敏感信息？

不要，建议用占位符替换 token 和私密参数。

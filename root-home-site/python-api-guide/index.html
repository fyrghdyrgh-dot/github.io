01

接口约定先写清楚

路径、参数、字段类型和错误码越早统一，后面返工越少。

02

日志与错误信息要可追踪

方便联调，也方便上线后排查。

03

示例请求比口头说明更有效

至少准备一组成功和一组失败示例。

CHECKLIST

上线前或交付前建议这样核对

  • 统一字段命名风格，不要中途切换大小写规则。
  • 把错误返回与权限问题分开说明，减少误判。
  • 上线前保留最小可复现请求样例。

FAQ

常见问题

接口文档应该什么时候补？

最好在联调前就写出最小版本，不要等上线后补。

示例返回值有必要写吗？

有，尤其是嵌套字段和错误返回。
